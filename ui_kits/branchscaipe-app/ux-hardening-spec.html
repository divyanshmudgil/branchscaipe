Branchscaipe · Phase 2

UX Hardening Specification

An audit of the Phase-1 prototype and a redesigned interaction model so every feature behaves consistently and predictably. The visual language is preserved; this is product behavior, information architecture, and state.

Scope: sidebar & panels, branching, merge, navigation, response actions, sharing, context inheritance. The companion Chat app card implements everything below.

01Audit — issues discovered

The Phase-1 build had a strong visual foundation but conflated several distinct concepts and faked others. The defects, grouped by severity:

Architecture-level (conflated concepts)

  • Sidebar and branch panel were the same surface. The sidebar never expanded; its toggle opened the branch menu. Two unrelated ideas — navigation chrome and branch hierarchy — were bound to one control.
  • Branch creation produced a separate "BRANCHSCAPE" landing instead of a thread. Branching felt like leaving the conversation, not continuing it — defeating the product's core promise.

Faked behavior (UI without function)

  • Merge showed a toast and an indicator but never inserted content. Copy and Retry did nothing. Share said "Link Copied" with no link.
  • Breadcrumb was decorative, not navigable. Branches couldn't be renamed.

Quality (felt unpredictable)

  • AI replies felt random because nothing carried parent / branch / merged context, so answers didn't connect to the thread they lived in.
  • No way to star a response, branch from a selection, or right-click a message — table-stakes affordances for an exploration tool were missing.

02Updated information architecture

Three independent surfaces, each with one job. Crucially, the navigation sidebar and the branch panel are now separate — collapsing the sidebar never hides your branches, and opening branches never resizes the sidebar.

Surface A — Sidebar

Persistent nav. Collapsed = icon rail (68px); expanded = labelled (264px). Its toggle only expands/collapses. Holds: New chat, Search, Branches, Starred, History, Settings, account.

Surface B — Panel

Secondary column raised by Branches / Starred / History. Never modal — the chat stays live beside it. Shows the lineage tree, starred responses, or full history.

Surface C — Thread

The conversation itself: breadcrumb (primary nav) + transcript + composer. A branch is rendered here identically to any chat.

Transients

Search, Settings, Merge → centered dialogs. Context menu & selection menu → floating, dismiss on outside-click / Esc / scroll.

Navigation rule: a branch is a first-class conversation, never an overlay. Switching to a branch === switching chats. There is no modal "branch mode."

03Branching interaction model

Every entry point ends in the same place: a new child thread opens immediately, inherits context up to the branch point, and the user lands in it. No landing screen, no intermediate page. The branch appears in the hierarchy instantly and is named by AI (one word, max three) — overridable.

04Context inheritance & AI quality

A branch inherits the transcript of every ancestor up to the point it forked, then its own messages. The model "sees" a flat, ordered context window assembled from the lineage:

contextMessages(branch) for each ancestor A in lineage(root → branch): if A has a child C on the path: include A.messages up to & including C.branchPointId else (A is the branch itself): include all of A.messages → ordered transcript = what the assistant conditions on

Replies are generated against that window, so a branch about Closure nested under Hooks answers with hooks context in scope. First replies in a branch open with a calm continuity cue ("Continuing from Hooks → State —") so the thread never feels disconnected. Merged content sets a _lastMerge marker the next reply acknowledges.

Conflict resolution

  • Append-only, never overwrite. Merged content is added after a divider; existing messages are untouched, so there is no destructive conflict to resolve.
  • Provenance preserved. Merged messages carry fromMerge: sourceId and render with a left accent rule, so it's always clear what came from where.
  • Lineage is a DAG, kept acyclic. A branch can't merge into itself or a descendant; merge targets exclude the source and its subtree, with ancestors ranked first.

05Merge interaction model

Merge genuinely inserts content into a user-chosen target, with a labelled divider and metadata. The source branch is always retained — never auto-deleted.

Merge response

One response → chosen parent/ancestor. Inserts: divider + that single message (flagged fromMerge).

Merge conversation

Current branch → chosen target. Inserts: divider + all of the branch's user/assistant messages.

doMerge({ scope, sourceId, target, sourceMsg? }) divider = { role:"merge", source, sourceId, scope, ts } inserts = scope==="response" ? [sourceMsg] : source.userAndAssistantMessages target.messages.push(divider, ...inserts.map(flag fromMerge)) setActive(target); flash(divider) toast: "Merged into · source kept" → divider reads: "Merged conversation from · 2 min ago", click to jump back

06Navigation model

The breadcrumb is the primary navigator and always emphasizes the current node.

short lineage React › Hooks › Closure › Example long lineage React › … › Closure › Example (… expands the full path)
  • Click any node → navigate immediately (same as switching chats). Current node is a non-link, emphasized pill.
  • Double-click a node (or rename via context menu / tree) → inline edit. Same rename works from the branch panel.
  • Ellipsis appears past 4 nodes; clicking expands to the full lineage with a calm transition.
  • Cross-surface jumps (Search result, Starred item, merge divider) navigate and flash the target message so you don't lose it.

08Edge cases handled

  • Empty branch: shows a one-line reassurance ("full context up to here, parent untouched") instead of a blank pane.
  • Rename to empty / whitespace: rejected, reverts to prior name. Esc cancels; Enter / blur commits.
  • Merge into self or descendant: impossible — excluded from target list, ancestors ranked first, parent labelled.
  • Deep lineage: breadcrumb collapses with an ellipsis; tree indents recursively and scrolls.
  • Selection branch with tiny / cross-element selection: ignored under 2 chars or if it escapes the response body.
  • Retry: regenerates in place (same message id) using the preceding user turn — no duplicate bubble.
  • Unstar from panel: reflects in the response immediately; empty Starred shows guidance, not a void.
  • Reload: branches, active thread, theme, density and sidebar state persist; position is restored.
  • Share when nothing to share: the link reflects the real scope (branch vs conversation); no fake "copied" without output.
  • Reduced motion: jump-flash and entrance animations respect prefers-reduced-motion.
